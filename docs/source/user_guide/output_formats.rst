==============
Output Formats
==============

Every artefact produced by the pipeline or by ``LigninExporter`` is
described here: file name, location, format, and content schema.

Directory layout
-----------------

After :meth:`~lignoforge.pipeline.pipeline.LigninPipeline.run` the output
directory contains::

    <output_dir>/
    ├── input_high_level.json
    ├── estimated_priors.json
    ├── simulation_parameters.json
    ├── chain_statistics.json
    ├── population_statistics.json
    ├── population.smi
    ├── atomistic_topology.json
    ├── coarse_grained_topology.json
    ├── coarse_grained_topology_viewer.html
    ├── pdb/
    │   ├── polymer_A.pdb
    │   ├── polymer_B.pdb
    │   └── ...
    └── pdb_cg/
        ├── polymer_cg_A.pdb
        ├── polymer_cg_B.pdb
        └── ...

JSON files
----------

``input_high_level.json``
~~~~~~~~~~~~~~~~~~~~~~~~~~

A copy of the validated pipeline input after schema checking.  This is
useful for reproducing a run exactly.  The file mirrors the structure
described in :doc:`input_format`.

``estimated_priors.json``
~~~~~~~~~~~~~~~~~~~~~~~~~~

A flat dictionary of all prior values used by the simulation.  Keys:

.. code-block:: json

    {
        "S_fraction":          0.47,
        "G_fraction":          0.47,
        "H_fraction":          0.06,
        "linkage_fractions": {
            "4-O-5":     0.04,
            "alpha-O-4": 0.05,
            "beta-O-4":  0.52,
            "5-5":       0.12,
            "beta-5":    0.14,
            "beta-beta": 0.10,
            "beta-1":    0.03
        },
        "Mn":              3200.0,
        "Mw":              8000.0,
        "PDI":             2.5,
        "mean_DP":         15,
        "max_DP":          55,
        "branching_index": 0.04,
        "condensation_degree": 0.30,
        "avg_monomer_MW":  187.2
    }

``simulation_parameters.json``
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

The keyword arguments that were passed to
:class:`~lignoforge.simulation.population.Simulation` (after prior
translation).  Inspect this file to understand exactly what parameter
values were used.

``chain_statistics.json``
~~~~~~~~~~~~~~~~~~~~~~~~~~

A JSON array with one record per accepted chain.  Each record is the
output of
:meth:`~lignoforge.core.characterization.Characterize.summary`.

.. list-table::
   :header-rows: 1
   :widths: 30 10 55

   * - Key
     - Type
     - Description
   * - ``monomer_count``
     - int
     - Total number of monomer units in the chain.
   * - ``H_count`` / ``G_count`` / ``S_count``
     - int
     - Absolute count of each monomer type.
   * - ``H_frac`` / ``G_frac`` / ``S_frac``
     - float
     - Molar fraction of each monomer (sums to 1.0).
   * - ``<linkage>_count``
     - int
     - Absolute count for each of the 7 linkage types.
   * - ``<linkage>_frac``
     - float
     - Fraction of total linkages (sums to 1.0).
   * - ``OCH3_count``
     - int
     - Methoxy substituent count.
   * - ``OH_count``
     - int
     - Hydroxyl substituent count.
   * - ``MW``
     - float
     - Molecular weight in g/mol (heavy atoms only unless hydrogens were
       added before characterization).
   * - ``branching_coeff``
     - float
     - Fraction of non-terminal monomers.
   * - ``smiles``
     - str
     - SMILES representation generated by pysmiles.

``population_statistics.json``
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Aggregate statistics over the full population.  For every numeric key in
``chain_statistics.json`` the file contains four sub-keys:

.. code-block:: text

    {
        "monomer_count": {"mean": 20.3, "std": 4.1, "min": 8, "max": 37},
        "G_frac":        {"mean": 0.94, "std": 0.03, "min": 0.85, "max": 1.0},
        ...
    }

Topology files
--------------

``atomistic_topology.json``
~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Full atomistic representation of all chains.  Top-level structure::

    {
        "chains": [
            {
                "chain_id": "A",
                "monomers": [
                    {
                        "monomer_index": 0,
                        "monomer_type":  "G",
                        "residue_name":  "GYU",
                        "atoms": [
                            {"atom_index": 0, "element": "C", "x": 1.2, "y": 0.4, "z": 0.0},
                            ...
                        ],
                        "bonds": [[0, 1], [1, 2], ...]
                    },
                    ...
                ],
                "inter_monomer_bonds": [[3, 14], ...]
            }
        ]
    }

Coordinate values (``x``, ``y``, ``z``) are present only if the
``generate_3d`` export option was enabled.  Residue names use the
three-letter PDB codes:

.. list-table::
   :header-rows: 1
   :widths: 20 20 55

   * - Monomer
     - Residue code
     - Notes
   * - H (p-hydroxyphenyl)
     - ``HPU``
     - HydroxyPhenyl Unit
   * - G (guaiacyl)
     - ``GYU``
     - Guaiacyl Unit
   * - S (syringyl)
     - ``SYU``
     - Syringyl Unit

``coarse_grained_topology.json``
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Reduced representation with one bead per monomer.  Bead positions are the
mass-weighted centre-of-mass (COM) of all atoms belonging to that monomer
in the atomistic 3-D structure, so the CG coordinates are fully consistent
with the atomistic topology::

    {
        "schema": "lignoforge-coarse-grained-population-v1",
        "chains": [
            {
                "chain_id": "A",
                "beads": [
                    {"bead_id": 0, "bead_type": "GYU", "x": 1.2, "y": 0.4, "z": -0.3},
                    ...
                ],
                "links": [[0, 1], [1, 2], ...]
            }
        ]
    }

``coarse_grained_topology_viewer.html``
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Self-contained HTML page with an interactive 3-D Plotly viewer.
Open in any browser — no server required.

- Bead colour encodes monomer type: H = red, G = green, S = blue.
- Backbone bonds (β-O-4, α-O-4) are drawn as solid lines.
- C–C cross-links (5-5, β-5, β–β, 4-O-5, β-1) are drawn as dashed lines.
- Bead positions are the COM-derived 3-D coordinates from the atomistic
  structure, giving a realistic spatial picture of chain morphology.
- Hovering over a bead shows the chain ID, bead index, and monomer type.

SMILES file
-----------

``population.smi``
~~~~~~~~~~~~~~~~~~~

Plain-text file with one SMILES string per accepted chain, one per line.
Deterministic ordering matches the chain-statistics array.  Suitable for
direct import into RDKit, ChemDraw or any other cheminformatics tool::

    $ head -3 output_dir/population.smi
    COc1cc(CC(CO)...)...
    COc1ccc(CC(CO)...)...
    ...

PDB files
---------

``pdb/polymer_<ID>.pdb`` (atomistic)
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Standard PDB format file for each accepted chain.  Each line is a
``HETATM`` record followed by ``CONECT`` records for all bonds::

    HETATM    1  C1  GYU A   1       1.234   5.678   0.000  1.00  0.00           C
    HETATM    2  C2  GYU A   1       2.456   5.700   0.000  1.00  0.00           C
    ...
    CONECT    1    2    7
    ...

Atomistic PDB files are generated automatically when ``generate_3d=True``
(the default).

``pdb_cg/polymer_cg_<ID>.pdb`` (coarse-grained)
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

VMD-compatible coarse-grained PDB.  Each monomer is represented by a
single pseudo-atom with atom name ``BB`` and the monomer residue code
(``GYU`` / ``SYU`` / ``HPU``).  ``CONECT`` records reproduce the
inter-monomer bond network (chain, branch, and ring-closing bonds)::

    HETATM    1  BB  GYU A   0       1.234   5.678   0.000  1.00  0.00          BB
    HETATM    2  BB  SYU A   1       3.456   4.700   1.200  1.00  0.00          BB
    ...
    CONECT    1    2
    ...

Coordinates are the COM-derived positions from the atomistic topology, so
both PDB files share the same coordinate frame and can be loaded together
in VMD for overlay visualisation.

.. tip::

   In VMD, load both files in the same molecule::

       vmd pdb/polymer_A.pdb pdb_cg/polymer_cg_A.pdb

.. _export-options-reference:

Export options reference
-------------------------

Export options control 3-D coordinate generation and parallelism.
They are passed inside ``simulation_overrides`` to
:meth:`~lignoforge.pipeline.pipeline.LigninPipeline.run`; the pipeline
extracts them before forwarding the remaining keys to the simulator::

    results = pipeline.run(
        simulation_overrides={
            "generate_3d":        True,
            "include_hydrogens":  True,
            "optimize_3d":        True,
            "max_uff_iterations": 300,
            "n_workers":          None,   # None = all CPU cores
        }
    )

.. list-table::
   :header-rows: 1
   :widths: 30 10 55

   * - Option
     - Default
     - Description
   * - ``generate_3d``
     - ``true``
     - Embed 3-D coordinates via RDKit ETKDGv3.
   * - ``include_hydrogens``
     - ``true``
     - Retain explicit hydrogens in the atomistic PDB output.
   * - ``optimize_3d``
     - ``true``
     - Run MMFF94 / UFF geometry optimisation after embedding.
   * - ``max_uff_iterations``
     - ``300``
     - Maximum geometry optimisation iterations.  A second pass of
       up to ``max_uff_iterations // 2`` is performed automatically
       if the first pass does not converge.
   * - ``n_workers``
     - ``None``
     - Number of parallel worker processes for 3-D embedding.
       ``None`` uses all logical CPU cores.  Set to ``1`` to
       disable parallelism.

.. note::

   3-D export runs in parallel across all available CPU cores by default.
   For very large populations (``n_population > 100``) on memory-limited
   machines, cap the workers with ``n_workers=4`` or similar.
